# Notebook_for_Linux
A security importance notebook software
# 备忘录

一个本地优先的 Markdown 备忘录：编辑与预览、SQLite 持久化、全文搜索、标签、待办、置顶、
自动保存，正文可选 AES-256-GCM 加密，笔记可带图片附件

预览由 Pango 富文本渲染，不依赖 WebKit

## 特点

- **本地优先**：单个 SQLite 文件，没有服务端，没有账号。数据就在你自己硬盘上
- **编辑 / 预览双页签**：写 Markdown 或看渲染随时切，两边是同一份正文的两个视图
- **中文搜索能用**：FTS5 + trigram 分词器，搜中文不用切词。短于 3 个字符的查询自动降级到
  `LIKE`，个人笔记量级下依然是毫秒级。边打边过滤，停止输入 180 毫秒后才查库
- **待办是真 Markdown**：勾选框就是正文里的 `- [ ]` / `- [x]`，点击预览里的复选框直接反写
  正文。不在数据库里另存一份，所以拿别的编辑器改完 Markdown 也能对上
- **自动保存**：停手 700 毫秒就落盘，不用按保存。也可以随时「文件 → 立即保存」
- **标题可留空**：留空就用正文首行，列表里也这么显示
- **图片附件**：按附件存 BLOB，按边长 72px 生成缩略图，点缩略图上的删除按钮删。不内联进
  Markdown，所以正文保持纯文本，好 diff、好同步
- **可选加密**：正文和图片字节用 AES-256-GCM 加密，口令用 PBKDF2-HMAC-SHA512（60 万次迭代）
  派生。忘了口令就取不回来

## 依赖

| 依赖 | 版本要求 | 用途 |
| --- | --- | --- |
| OCaml | >= 5.0 | 语言 |
| dune | >= 3.0 | 构建 |
| lablgtk3 | 任意 | GTK+ 3 绑定 |
| sqlite3 | 任意 | 存储 |
| cryptokit | 任意 | 加密 |

系统侧还需要 GTK+ 3 开发库：

```sh
# Debian / Ubuntu
sudo apt install libgtk-3-dev

# Fedora
sudo dnf install gtk3-devel

# Arch
sudo pacman -S gtk3
```

## 编译与安装

```sh
opam install lablgtk3 sqlite3 cryptokit
opam install .          # 或者在项目目录里直接跑，见下
```

不想装成 opam 包也可以直接跑：

```sh
eval $(opam env)
dune build
dune exec notebook -- /path/to/notes.db    # 可选的数据库路径
```

装成 opam 包：

```sh
opam install .
notebook                                  # 装好后直接用
```

## 用法

启动：

```sh
notebook                                   # 用默认数据库位置
notebook ~/notes/my.db                    # 指定数据库文件
```

数据库位置的优先级：

1. 命令行给的路径
2. `$NOTEBOOK_DB`
3. `$XDG_DATA_HOME/notebook/notebook.db`
4. `~/.local/share/notebook/notebook.db`

目录不存在会自动创建（权限 `0700`）。

### 支持的 Markdown 语法

预览支持这些：

| 语法 | 效果 |
| --- | --- |
| `# 标题` … `###### 标题` | 标题 |
| `**粗体**` | 粗体 |
| `*斜体*` 或 `_斜体_` | 斜体 |
| `~~删除线~~` | 删除线 |
| `` `代码` `` | 行内代码（灰底） |
| `> 引用` | 引用块 |
| `- ` / `* ` / `+ ` | 无序列表 |
| `1. ` | 有序列表 |
| `- [ ]` / `- [x]` | 可点击的待办复选框 |
| `---` | 分隔线 |
| ``` 围栏代码块 | 等宽、不解析内部语法 |

注意：这是自己写的渲染器，不是完整 CommonMark。表格、脚注、HTML 块、链接渲染都不支持。
正文里的普通文本不会被当成 HTML，Pango markup 会被转义，所以 `<script>` 之类只会显示成字面量。

## 图片附件

「文件 → 附加图片…」或附件栏上的「附加图片…」按钮，会打开文件选择框。

- 上限 **20 MB**，超过会明确报错。
- 收不收只看 gdk-pixbuf 能不能解码，而不是看后缀。实际能用的大致是 PNG、JPEG、GIF、BMP、
  WebP、TIFF。选到解码不了的会直接拒绝，**并且不会写进数据库**。
- 存的 MIME 类型是按后缀猜的（`.jpg` / `.jpeg` / `.tif` / `.tiff` 都认），只是为了以后导出
  或换程序读的时候有个字段可用；真正把关的是解码那一步。
- 缩略图按边长 72px 等比缩放，宽图出来是扁的、竖图出来是窄的，比例不失真。
- 点缩略图上的删除按钮会先问你一句，确认了才删。
- 同一张图片可以被多条笔记引用；只有最后一个引用被删掉，图片本体才回收。

图片按附件存而不是内联进正文，所以正文的字节完全可控 —— 你可以用别的工具直接读写 `.db`，
或者把 Markdown 单独复制出来贴到别处。

## 加密

「安全 → 启用正文加密…」设一个口令。

**加密范围**：笔记正文、图片字节。

**不加密**：标题、标签、置顶状态、时间戳、笔记和图片的关联关系。

这是故意的：不加密标题和标签就没法搜索和排序，列表会变成一列乱码。关联关系同理 ——
不然连「这条笔记有几张图」都问不出来。所以拿到 `.db` 文件的人仍然能看出你有多少条笔记、
每条的修改时间和标题，但读不到正文。

参数：

- 密钥派生：PBKDF2-HMAC-SHA512，600,000 次迭代，16 字节随机盐
- 加密：AES-256-GCM，32 字节密钥，每次加密换新的 12 字节随机 nonce
- 认证：GCM 自带认证标签，口令错或密文被改过都会明确报错，不会静默返回垃圾

口令只用来派生密钥，**不存储、不校验**。加密开启后，钥匙串里只有那把派生出来的密钥；
口令忘了没有任何找回途径，只能放弃这个数据库

启动时如果库是加密的，会先弹口令框再加载列表，最多给三次机会

启停加密都会顺带把已存的图片字节一起转换，不需要单独处理

## 开发

### 代码结构

```
bin/main.ml            入口，只负责解析那一个可选的数据库路径
lib/core/              纯逻辑，不依赖 GTK，好测试
  model.ml             笔记、图片元数据、标题兜底、排序
  crypto.ml            PBKDF2、AES-GCM、密钥生命周期
  sqlite_store.ml      schema、迁移、CRUD、加密解锁、FTS、搜索
  markdown.ml          Markdown 解析、待办反写、统计
  render.ml            渲染成 Pango markup（和 GTK 解耦）
lib/view/              GTK 那层
  app.ml               主窗口、状态机、自动保存、图片附件
  preview.ml           TextTag 渲染 + 点复选框
  dialogs.ml           输入/密码/确认/错误对话框
test/test_core.ml      核心测试（不需要显示环境）
test/gui_smoke.ml      GUI 冒烟测试（需要显示环境）
```

`lib/core` 里没有任何 GTK 依赖，所以绝大部分逻辑可以不开窗口就测。

### 跑测试

```sh
dune build @all
dune test                              # 核心，208 项，不需要显示环境
./_build/default/test/gui_smoke.exe    # GUI，66 项，需要显示环境
```

GUI 冒烟测试会真的开窗口、发真实的信号、再回读数据库，不是 mock。它不在 `dune test` 里，
所以在没有显示环境（CI、ssh）的情况下 `dune test` 不会因此失败

跑 GUI 测试需要一个显示环境：

```sh
xvfb-run -a ./_build/default/test/gui_smoke.exe   # 没有物理显示器时
```

### SQLite schema

```
note        正文、标题、时间戳、置顶
tag         标签名
note_tag    笔记 ↔ 标签
image       图片 BLOB、MIME、宽高、字节数
note_image  笔记 ↔ 图片，带 pos 决定顺序
note_fts    FTS5 虚表（trigram），标题 + 正文
crypto_meta KDF 参数、盐、是否已加密
```

`note_image` 的外键带 `ON DELETE CASCADE`，删笔记时关联自动清掉；图片本体由
`gc_orphan_images` 显式回收，所以共享图片不会被误删。

`CREATE TABLE IF NOT EXISTS` 意味着老库直接打开就升级，不用手动迁移。

### 几个实现上的选择

**为什么自己写 Markdown 渲染，不用 WebKit。** WebView 是几百 MB 的依赖，而且在
`libwebkit2gtk` 出来之前根本没有 OCaml 绑定。自己解析 + Pango 富文本，依赖只有 GTK 本身，
冷启动也快。代价是不支持完整 CommonMark（见上面的语法表）。

**为什么图片存 BLOB 而不是存文件路径。** 好处是加密、备份、删除都跟着数据库走，没有
「数据库在、文件丢了」的孤儿状态。代价是数据库会变大。如果你更想要文件旁路（比如放到
`~/.local/share/notebook/media/`），得改 `sqlite_store.ml` 的 `insert_image`。

**为什么待办状态存在正文里。** 见上面「待办是真 Markdown」。

**为什么标题和标签不加密。** 见上面「加密」。

## 已知限制

- 没有键盘快捷键。
- Markdown 不是完整 CommonMark，见上面的语法表。
- 撤销 / 重做没做。
- 单条笔记的大小没有上限（图片有 20 MB 上限）。
- 加密库的口令无法找回。
